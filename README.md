# 말씀암송

녹음된 말씀을 듣고, 원하는 구간(시작~끝)을 정해 **계속 반복**해서 들으며 외우는 앱.
소리가 나오는 동안 **읽고 있는 글자가 금색으로 칠해진다**(가라오케).

React + Vite 정적 사이트. 서버·DB 없음. PWA(홈 화면 추가, 오프라인 재생).

## 실행

```bash
npm install
npm run dev       # 개발 서버 (http://localhost:5173)
npm run build     # dist/ 생성 → 이 폴더를 그대로 올리면 배포 끝
npm run preview   # 빌드 결과 미리보기 (서비스 워커 포함 확인용)
```

## 사용법 (구절 화면)

| 하고 싶은 것 | 방법 |
|---|---|
| 전체 반복 | 큰 재생 버튼 |
| 한 절만 반복 | 본문 왼쪽 **절 번호** 누르기 (한 번 더 누르면 해제) |
| 여러 절 반복 | 구간 반복 → **절로 고르기** `3절 ~ 5절` |
| 원하는 지점 반복 | 재생 중 **여기부터 / 여기까지**, 진행바의 **A·B 손잡이** 끌기, ±0.1 / ±0.5초 미세조절 |
| 반복 횟수·쉼·속도 | 반복 설정: 횟수 ∞/1/3/5/10, 반복 사이 쉬는 시간 0~3초, 속도 0.75/1/1.25배(음높이 유지) |
| 그 단어부터 듣기 | 본문의 단어 누르기 |
| 외웠는지 확인 | 더보기 → **단어 가리기** (가린 단어는 소리가 읽는 순간 드러남) |

키보드: `Space` 재생/일시정지, `[` 여기부터, `]` 여기까지, `Esc` 정지.

구간·설정·암송 완료는 기기 브라우저(localStorage)에 저장된다. 기기마다 따로다.

## 글자 색칠은 어떻게 맞추나

녹음에는 절·단어별 시간 정보가 없다. 그래서 구절을 열 때 브라우저가 녹음을 직접 분석한다 (`src/lib/align.js`).

1. 소리 크기를 10ms 단위로 재서 **짧은 쉼**들을 찾는다.
2. 쉼 사이 말소리 덩어리를 어절들에 순서대로 짝짓는다. 한국어는 음절 하나를 거의 같은 길이로 읽으므로, **덩어리 길이 ≈ 음절 수 × 발화 속도**가 되게 맞춘다. 긴 쉼은 절 끝·쉼표 뒤에 오는 쪽을 선호한다.
3. 덩어리 안에서는 음절 수에 비례해 시간을 나눈다.

음성 인식이 아니라 추정이다. 절 경계는 거의 맞고, 긴 절 안에서는 한두 어절씩 밀릴 수 있다.
어긋나면 **더보기 → 타이밍 맞추기**를 쓴다. 재생을 들으며 새 절이 시작될 때 버튼을 누르면 된다.
조금 늦게 눌러도 가까운 말소리 시작점에 붙는다. 맞춘 절 경계에 맞춰 어절 시간이 다시 계산된다.

자동 맞추기 결과를 터미널에서 확인하기:

```bash
npm run check-align            # 전체 구절 요약 (절 시작 시각)
npm run check-align -- s1-02   # 한 구절의 어절별 시간
```

## 본문·녹음 고치기 / 추가하기 (앱 코드 수정 불필요)

- 본문: `public/data/passages.json`. 오타는 여기서 고치면 된다.
- 녹음: `public/audio/<id>.mp3`. JSON의 `"audio": "audio/<id>.mp3"`로 연결한다. `null`이면 "아직 녹음이 없어요"가 표시된다.
- 새 구절이나 3단계는 `stages` 배열에 같은 모양으로 추가하면 된다. 목록 탭이 자동으로 생긴다.
- 글자 색칠은 새 녹음에서도 자동으로 동작한다.

WAV 녹음을 기존과 같은 형식으로 바꾸기 (모노 32kHz 48kbps, 앞뒤 무음 정리, 음량 맞춤):

```bash
node scripts/wav2mp3.mjs ../data/1_12.wav public/audio/s1-12.mp3
```

(`s1-12` 요한복음 1:1-18, `s1-13` 요한복음 15:1-17 녹음은 이 방법으로 `../data/*.wav`에서 만들어 넣었다.)

## 배포

`npm run build` 후 `dist/`를 정적 호스팅에 올린다. `base: './'`라서 하위 경로에서도 동작한다.

- **GitHub Pages**: `dist/` 내용을 `gh-pages` 브랜치에 올리거나 Pages 액션을 쓴다.
- **Cloudflare Pages / Netlify**: 빌드 명령 `npm run build`, 출력 폴더 `dist`. `public/_headers`가 서비스 워커 캐시를 막아 준다.

본문이나 녹음을 바꾼 뒤에는 다시 빌드해서 올린다. 캐시 구조를 바꿨다면 `public/sw.js`의 `VERSION`을 올린다.

## 저작권 안내

- 본문은 **개역개정**으로 보이며, 저작권은 대한성서공회에 있다. **누구나 접근할 수 있게 공개 배포하기 전에 대한성서공회의 이용 허가 절차를 확인해야 한다.** 그 전까지는 링크를 아는 소수(본인·가족·모임)만 쓰도록 한다.
- 본문은 교재 사진에서 사람이 옮겨 적은 것이라 오타가 있을 수 있다.
- 녹음은 사용자가 직접 한 것이다.

```
public/data/passages.json   본문 (1단계 13, 2단계 21 구절)
public/audio/*.mp3          녹음
public/sw.js                서비스 워커 (오프라인)
src/lib/looper.js           구간 반복 재생기 (<audio> + requestAnimationFrame)
src/lib/align.js            녹음 ↔ 본문 자동 맞추기
src/lib/timing.js           브라우저에서 녹음 분석, 직접 맞춘 절 경계 반영
src/components/Karaoke.jsx  본문 + 글자 색칠
src/components/Player.jsx   하단 플레이어 (진행바, A·B 손잡이)
src/screens/                목록 / 구절 화면
scripts/                    wav→mp3 변환, 자동 맞추기 점검
reference/prototype.html    처음 프로토타입 (참고용)
```
